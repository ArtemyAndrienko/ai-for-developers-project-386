## Функциональные сценарии

Сервис работает по модели «владелец календаря → посетитель»: первый создаёт встречу со свободными
интервалами, второй записывается на один из этих интервалов. Приложение состоит из трёх экранов
(по референсам): лендинг с навигацией «Записаться» / «Предстоящие события», экран «Запись на
звонок» и экран «Предстоящие события».

### Сценарий 1. Создание встречи

**Участник:** авторизованный владелец календаря.
**Цель:** создать встречу, разбитую на интервалы указанной продолжительности, на которые смогут
записываться другие пользователи.
**Предусловия:** в профиле пользователя заданы границы рабочего дня — время начала и время окончания
(по умолчанию 09:00–18:00) и длительность интервала (по умолчанию 30 минут). Полный рабочий день по
умолчанию даёт 18 слотов.

**Ход сценария:**

1. Пользователь открывает форму создания встречи и заполняет поля:
   - название — обязательно;
   - описание — необязательно;
   - продолжительность интервала — обязательна (например, 15 / 30 / 60 минут);
   - дата встречи — задаётся выбором дня в календаре справа, а не ручным вводом.
2. Справа от формы отображается календарь с окном доступности 14 дней. В референсе он реализован
   как сетка месяца (недели Пн–Вс) с кнопками листания по неделям ← / → и заголовком месяца
   («март 2026 г.»).
3. В ячейке каждого доступного дня отображается количество свободных слотов (бейдж вида «18 св.»).
   Дни в прошлом и дни за пределами 14-дневного окна подсвечены серым и не выбираются.
4. При выборе дня правее календаря показывается список интервалов заданной продолжительности:
   рабочий день разбивается от времени начала до времени окончания с шагом, равным продолжительности
   (например, «09:00 - 09:30», «09:30 - 10:00», …).
5. Если остаток дня короче указанной продолжительности, этот хвостовой интервал отображается серым:
   он виден, но не выбирается.
6. Пользователь выбирает интервал — он становится временем начала встречи, окончание считается как
   `начало + продолжительность`. Выбранный интервал подсвечивается (акцентная рамка).
7. Пользователь сохраняет встречу: кнопка сохранения («Продолжить» / «Сохранить») неактивна, пока
   не выбран интервал.

**Статусы интервалов:**

| Статус | Вид | Можно выбрать |
| --- | --- | --- |
| Свободный | обычный, метка «Свободно» | да |
| Выбранный | акцентная подсветка | — |
| Занятый (уже забронирован) | серый, метка «Занято» | нет |
| Хвостовой остаток дня короче продолжительности | серый | нет |

**Проверки при сохранении:**

- название непустое, длина в пределах лимита;
- продолжительность — положительное значение из допустимого диапазона;
- выбранный интервал лежит внутри рабочего дня выбранной даты и не пересекается с уже занятыми;
- выбранный интервал не в прошлом и входит в 14-дневное окно доступности.

Ошибки показываются рядом с полем, встреча не сохраняется.

**Результат:** после сохранения отображается список всех встреч пользователя, включая только что
созданную. Если встреч нет, список пустой — показывается пустое состояние с предложением создать
первую встречу.

**Граничные случаи:**

- рабочий день короче одной продолжительности → единственный хвостовой интервал показан серым,
  выбрать нечего, сохранение недоступно с подсказкой уменьшить длительность или сдвинуть границы дня;
- день без свободных интервалов → бейдж «0 св.» или его отсутствие, все интервалы в списке помечены
  как занятые;
- интервалы строятся в часовом поясе профиля, при смене настроек рабочего дня пересчитывается
  только то, что ещё не забронировано.

### Сценарий 2. Запись на свободное время

**Участник:** любой пользователь, аккаунт не требуется — запись идентифицируется по e-mail.
**Цель:** выбрать доступную встречу, забронировать свободный интервал и увидеть свои записи.
**Предусловия:** у владельца календаря есть хотя бы одна встреча со свободными интервалами.

**Ход сценария:**

1. Пользователь открывает экран «Запись на звонок» (кнопка «Записаться» с лендинга) и выбирает
   встречу из доступных. Экран состоит из трёх колонок:
   - «Информация» — карточки «Выбранная дата», «Выбранное время», «Свободно» (число слотов дня),
     «Длительности в дне»; до выбора в них отображаются «Дата не выбрана», «Время не выбрано»;
   - «Календарь» — тот же сеточный календарь с окном 14 дней и бейджами свободных слотов по дням;
   - «Статус слотов» — пока день не выбран, показывается подсказка «Выберите дату в календаре.»,
     кнопка «Продолжить» неактивна.
2. Пользователь выбирает день — в «Статусе слотов» появляется список интервалов дня со статусами
   «Свободно» / «Занято»; занятые и хвостовые интервалы неактивны.
3. Пользователь выбирает свободный интервал (подсветка, «Выбранное время» обновляется) и нажимает
   «Продолжить». Кнопка «Назад» возвращает к предыдущему шагу без потери выбора.
4. Открывается блок «Подтверждение записи»: поля «Имя» и «Email», кнопка «Подтвердить запись»,
   кнопка «Изменить» для возврата к выбору слота.
5. При подтверждении система проверяет конфликт: если интервал успели забронировать, показывается
   ошибка «слот занят» и пользователь возвращается к выбору слота.
6. Успешная запись: «Бронь подтверждена. До встречи!» с кнопкой «Забронировать ещё» (повторная
   запись в том же окне). Занятый слот немедленно становится неактивным («Занято»), счётчики
   пересчитываются («Свободно 18» → «Свободно 17», бейдж дня «18 св.» → «17 св.»).
7. Пользователю отображается экран «Предстоящие события» со списком его записей; карточка записи
   содержит имя, e-mail, начало слота («Слот: 2026-03-28-09:00») и дату создания записи
   («Создано: 27.03.2026, 14:40»). Если записей нет — пустой список с предложением записаться.

**Проверки и конфликты:**

- имя и e-mail обязательны, e-mail валиден;
- запись невозможна на занятый, прошедший или серый (недостаточный) интервал;
- повторная запись на тот же интервал блокируется проверкой конфликта.

**Отображение статуса встреч:**

- по умолчанию список делится на две группы: «Предстоящие» и «Прошедшие»;
- как только время встречи закончилось, она переносится в группу «Прошедшие» — отдельно
  перемаркировать её вручную не нужно;
- «Прошедшие» отображаются по умолчанию и скрываются по кнопке «Скрыть неактуальное»
  (повторное нажатие — «Показать неактуальное», выбор состояния сохраняется для пользователя).

**Результат:** пользователь видит предстоящие встречи с датой, временем, названием и контактами,
а прошедшие — в отдельной свёрнутой группе. Отменённая владельцем встреча удаляется из списков
посетителя, её интервал снова становится свободным для записи.
